
This directory contains the data pipeline and model training components for generating semantic embeddings from the arXiv dataset.
### Technical Objective

The primary objective is to process the raw TeX source of the arXiv dataset and train a Hierarchical Network (H-Net) model. This model learns to segment byte-level data into semantically meaningful chunks, providing a rich feature representation for downstream embedding and indexing tasks. .

### Execution Workflow

The pipeline consists of three sequential stages.

**1. Data Ingestion: `Fastawsdownloader.py`**

This script downloads the bulk arXiv source dataset from the public `s3://arxiv` bucket.

*   **Function**: It parses the `arXiv_src_manifest.xml` to build a download queue. A progress log (`download_progress.jsonl`) and MD5 validation ensure download integrity and allow for efficient resumption.
*   **Configuration**: Key parameters like `DOWNLOADER_COUNT`, `DOWNLOAD_DIR`, and S3 retry configurations are defined as constants at the top of the file.
*   **Execution**:
    ```bash
    # Ensure LOCAL_MANIFEST_PATH points to your manifest file
    python3 Fastawsdownloader.py
    ```
    This will populate the `arxiv_downloads/src/` directory with `.tar` archives.

**2. Data Serialization: `tex2arrow.py`**

This script processes the downloaded `.tar` archives and serializes the raw TeX source into the Apache Arrow format.

*   **Function**: It uses a `concurrent.futures.ProcessPoolExecutor` to parallelize the `process_tar` function. This function extracts TeX content from multiple formats (`.tex`, `.tex.gz`, nested `.tar.gz`) and writes the structured data to the `out/` directory.
*   **Execution**:
    ```bash
    # Ensure SRC_DIR and OUT_DIR are configured correctly
    python3 tex2arrow.py
    ```

**3. Model Training: 'train_hnet.py`**

This script trains the H-Net language model on the processed dataset.

*   **Function**: It initializes the `HNetLM`, which wraps the core `HNet` architecture defined in the `hnet/` directory. The training loop computes a combined loss (`ar_loss` + `aux_loss`) and handles optimization.
*   **Current State**: The script is currently configured for the `enwik8` dataset via a `TextSamplerDataset`. It requires modification to load data from the `.arrow` files generated by `tex2arrow.py`.

### Apache Arrow: Data Serialization Format

We use Apache Arrow as the intermediate storage format between raw data extraction and model training.

**What is Apache Arrow?**

Arrow is a language-agnostic, columnar in-memory data format. Unlike row-oriented formats (like JSONL or CSV), which store all values for a single record contiguously, Arrow stores all values for a single column contiguously. This structure is highly optimized for analytical query performance and is a de-facto standard for ML data pipelines.

**Why We Use Arrow in This Pipeline**

1.  **Zero-Copy Reads**: Modern ML frameworks like PyTorch and libraries like Polars can read Arrow data directly into memory without any costly deserialization steps. This significantly speeds up data loading during training.
2.  **Schema Enforcement**: Arrow mandates a strict, typed schema. This ensures data integrity across our entire dataset, preventing errors from malformed records or inconsistent data types.
3.  **Scalability & Efficiency**: The columnar format is highly compressible and allows for efficient reads of only the columns required, which is critical when working with large-scale datasets like arXiv.

**Implementation in `tex2arrow.py`**

The script defines a clear schema for our data:

```python
# Arrow schema: one row per paper
SCHEMA = pa.schema([
    pa.field("paper_id",         pa.string()),
    pa.field("full_tex",         pa.string()),
    pa.field("source_tar",       pa.string()),
    # ... other metadata fields
])
```

It then creates a file writer and processes data in batches to manage memory usage effectively.

```python
# Open the output file for writing
sink   = pa.OSFile(str(out_path), "wb")

# Create an Arrow IPC (Inter-Process Communication) file writer
writer = ipc.new_file(sink, SCHEMA)

# Process records in a buffer
buffer = []
for pid, chunks in grouping.items():
    buffer.append({ ... })

    # When the buffer is full, convert to a RecordBatch and write
    if len(buffer) >= BATCH_SIZE:
        batch = pa.RecordBatch.from_pylist(buffer, schema=SCHEMA)
        writer.write_batch(batch)
        buffer.clear()
```

This approach creates self-contained, schema-complete `.arrow` files that are ready for high-performance consumption by the training script.
